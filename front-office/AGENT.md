## 개요
이 프로젝트는 웹 프로그래밍 팀 프로젝트로 진행하는 축제 정보 웹이야.
관리자는 축제를 생성/관리 할 수 있고, 유저는 진행중인 축제에 대한 전반적인 정보를 조회할 수 있어.

## 목적

- 프로젝트를 매번 처음부터 세팅하는 문제 해결을 위해
- 신규로 진행할 프로젝트들의 메인 기술 스택과 버전을 통일하기 위해
- 어드민 페이지를 해당 템플릿 디자인으로 내용만 바꿔서 빠르게 완성하기 위해
- 컴포넌트를 재활용하기 위해

## 기술 스택

- Next.js 16 (App Router)
- React 19
- TypeScript
- Tailwind CSS 4
- TanStack React Query
- Jotai (상태 관리)
- shadcn/ui + Radix UI
- ESLint + Prettier + Husky

## src 폴더 구조

- `/app`
  - Next.js App Router 기반 페이지 및 컴포넌트
  - `/(pages)` - 라우트 그룹 (어드민 페이지들)
  - `/components` - 공용 컴포넌트
  - `/hooks` - 커스텀 훅
  - `/layouts` - 레이아웃 컴포넌트
  - `/providers` - React Provider (QueryClient, Theme 등)
  - `/shadcn` - shadcn/ui 컴포넌트
  - `/styles` - 글로벌 스타일
  - `/util` - 유틸리티 함수
- `/atoms`
  - Jotai 아톰 (전역 상태 관리)
- `/theme`
  - 테마 관련 설정 및 변수

## 코드 작성 시 규칙

- 범용 유틸을 만들기 위한 과도한 일반화는 지양합니다.
- 주석에는 당연한 내용 대신 꼭 필요한 내용만 작성합니다.
- 기존 동작 변경이 필요한 경우 새로운 함수로 추가합니다.
- 여러 곳에서 사용될 가능성이 있으면 `src/app/components` 폴더에 컴포넌트를 생성합니다.
- 페이지에 귀속되지만 가독성을 위한 일회성 컴포넌트/함수는 페이지 라우터와 동일한 depth에 `./(components)` 경로로 생성합니다.
- **(중요)** 동일한 함수 혹은 변수여도 의미와 책임이 다른 경우 일부 중복을 허용합니다.
- React Server Component는 사용하지 않습니다.

## 구조 변경 관련 주의사항

- 기존 폴더 구조 변경은 매우 신중해야 합니다.
- 경로 변경은 하위 프로젝트의 import 및 build 과정에 직접적인 영향을 줍니다.
- 구조 변경이 필요한 경우 반드시 사전 논의 후 진행합니다.
